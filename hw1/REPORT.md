# HW1 — краткий отчёт

## 1. Цель

Реализовать преобразование набора регулярных выражений языка Funny в ε-НКА, затем в ДКА и минимальный ДКА.

## 2. Реализация

Использованы:

- конструкция Томпсона для regex → ε-NFA;
- epsilon-closure и subset construction для ε-NFA → DFA;
- Hopcroft для минимизации DFA;
- явная ловушка для непокрытых символов ASCII.

## 3. Спецификация

Основные правила:

```text
IDENT      [A-Za-z_][A-Za-z0-9_]*
INT        0|[1-9][0-9]*
WS         [ \t\r\n]+
COMMENT    //[^\n]*
```

Ключевые слова:

```text
function returns uses while if else true false
assert assume invariant length
```

Операторы и разделители:

```text
+ - * / == != <= >= < > = , ; ( ) [ ] { }
```

WS и COMMENT пропускаются.

## 4. Размеры автоматов

Запуск:

```bash
python main.py build
```

Фактические числа:

```text
ε-NFA:       1247 states
DFA:         342 states
minimal DFA: 88 states
```

## 5. Ловушка

ДКА делается полным относительно ASCII. Для отсутствующих переходов используется rejecting trap state с петлёй по всему ASCII-алфавиту.

## 6. Тестирование

Проверяются:

- пустая строка;
- whitespace;
- `0`;
- `00`, `01`;
- идентификаторы с `_`;
- ключевые слова;
- префиксы ключевых слов;
- операторы и разделители;
- комментарии `//...`;
- неизвестный ASCII-символ;
- non-ASCII;
- longest match (`==`, `<=` и т.д.).

Команда:

```bash
python main.py test
```

## 7. Результат

Все автоматические проверки должны завершаться `PASS`.

## 8. Примечание

`00` и `01` при заданном `INT = 0|[1-9][0-9]*` лексически разбиваются на отдельные `INT`-токены (`0`,`0` и `0`,`1`). Если спецификация курса требует диагностировать такие последовательности целиком, необходимо добавить отдельное правило ошибки перед `INT`.
